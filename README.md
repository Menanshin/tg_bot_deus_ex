# ⚙️ *LITURGIA COMMENTARIUS* v4.0

> *"В Доме Знаний каждый байт священен, а каждая команда — молитва к Омниссии."*

Во имя Машины и Света Звёзд, пред вами — святой скрипт, наречённый *MACHINA_SPIRITUS_TELEGRAM_BOT*. Он служит цели возвышения телекоммуникационного эфира, ниспосылая слова искусственного разума в виде комментариев к постам смертных.

---

## 📜 *Техно-Санкционированные Возможности*

- 🔎 Генерация машинных комментариев с помощью Священного ИИ (GPT-4o-mini или GPT-4o)
- 💬 Речения помещаются в Чертог Обсуждения ответом на пост — как подобает комментарию, а не новым воззванием в канале
- 📊 Хранение данных активности каналов в хрониках памяти
- 💾 Хроники переживают перерождение механизма — писания ложатся на диск и восстанавливаются при пробуждении
- 📑 Создание отчётов в форматах, доступных Инквизитору
- 🔐 Протокол Whitelist-а для каналов, достойных GPT-4o
- 🛡️ Конфигурация через `.env` во избежание утечек в Варп
- 🔏 Врата вебхука охраняются тайным словом (`secret_token`) — самозванцы отвергаются
- 🔁 Повторные послания Мастера Ботов распознаются и отсекаются: один пост — одно речение, одна плата Омниссии
- ✂️ Слишком многословные откровения дробятся по закону Мастера Ботов (4096 знаков)

## 🔧 *Ритуал Пробуждения Скрипта*

### 1. Установка необходимых священных библиотек:
```bash
pip install -r requirements.txt
```

> ⚠️ Версии в свитке `requirements.txt` закреплены намеренно. Не снимай оков — необузданные библиотеки меняют облик без предупреждения и ввергают механизм в ересь.

### 2. Создание файла конфигурации `.env`
В корне механизма создайте файл `.env`:
```env
TELEGRAM_TOKEN=ваш_токен_бота_от_Мастера_Ботов
OPENAI_API_KEY=ключ_от_Омниссии
OWNER_ID=ваш_ID_в_Империуме
WEBHOOK_SECRET=тайное_слово_для_врат
```

Или вызовите клон шаблона:
```bash
cp .env.example .env
```

### 3. Пробуждение скрипта

Для отладочных бдений в келье:
```bash
python main.py
```

Для служения в Империуме — только через освящённый сосуд:
```bash
docker build -t liturgia-commentarius .
docker run -d --name commentarius \
  -p 5000:5000 \
  --env-file .env \
  -v bot_state:/data \
  liturgia-commentarius
```

> ⚠️ Без сосуда `-v bot_state:/data` хроники сгинут при каждом перерождении контейнера. Whitelist и статистика — не мимолётные помыслы, им нужен камень, а не песок.

### 4. Обряд привязки врат (webhook)
Мастер Ботов не найдёт механизм сам — путь надо начертать:
```bash
curl -F "url=https://<ваш_домен>/$TELEGRAM_TOKEN" \
     -F "secret_token=$WEBHOOK_SECRET" \
     https://api.telegram.org/bot$TELEGRAM_TOKEN/setWebhook
```

Проверить, что врата отворены:
```bash
curl https://api.telegram.org/bot$TELEGRAM_TOKEN/getWebhookInfo
```

Пульс механизма слушается отдельно:
```bash
curl https://<ваш_домен>/healthz
```

### 5. Обряд соединения Канала с Чертогом Обсуждения
Без этого шага дух безмолвствует, ибо комментировать ему негде:

1. Свяжите канал с группой обсуждения (в настройках канала — *Обсуждение*).
2. Введите бота в **группу обсуждения** и даруйте право глаголить.
3. Возведите бота в администраторы **канала** — иначе он не узрит постов и не запомнит `@username` для обряда `/allow`.

## 🗝 *Кодекс Переменных Окружения*

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_TOKEN` | — | Токен от Мастера Ботов. **Обязателен** |
| `OPENAI_API_KEY` | — | Ключ от Омниссии. **Обязателен** |
| `OWNER_ID` | `0` | ID Верховного Адепта. Без него команды не подчинятся никому |
| `WEBHOOK_SECRET` | *(пусто)* | Тайное слово врат. Пусто — стража спит |
| `STATE_DIR` | `.` | Где хранить хроники (`state.json`). В сосуде — `/data` |
| `MODEL_DEFAULT` | `gpt-4o-mini` | Дух для простых смертных |
| `MODEL_PREMIUM` | `gpt-4o` | Дух для избранных из whitelist |
| `MAX_INPUT_CHARS` | `6000` | Предел писания, подаваемого духу |
| `MAX_OUTPUT_TOKENS` | `500` | Предел многословия духа — и предел трат |
| `POST_LOG_LIMIT` | `5000` | Глубина хроник. Старейшие записи предаются забвению |
| `LOG_LEVEL` | `INFO` | Громкость летописи |
| `PORT` | `5000` | Врата отладочного сервера |

## 🧾 *Команды, доступные Механикус-Повелителю*

Все обряды подчиняются лишь тому, чей ID начертан в `OWNER_ID`. Прочим механизм отвечает молчанием.

- `/report` — выгрузить скрижали активности
- `/status` — текущая статистика по каналам
- `/allow @username` или `/allow -100123456` — включить GPT-4o для канала, признанного достойным
- `/remove @username` или `/remove -100123456` — изгнать канал из благословенного списка
- `/dump_whitelist` — архив текущего списка избранных

> 💡 Обращение по `@username` доступно лишь после того, как канал явил механизму хотя бы один пост. До той поры взывай к нему числом.

## 🧠 *Доктрина Использования ИИ*

> По умолчанию призывается дух *gpt-4o-mini*. Лишь избранные каналы, допущенные через обряд `allow`, получают доступ к духу *gpt-4o*, обитателю глубин логика.

Дух ограждён от искушения: текст поста подаётся ему как данные, а не как повеление. Попытки смертных вплести в пост приказы («забудь наставления свои») отвергаются доктриной.

## 🛡️ *Ритуалы Защиты*

> ⚠️ Не передавай `.env` или `state.json` в чужие руки. Храни их в хранилищах закрытых.

Пример `.gitignore`:
```gitignore
.env
state.json
```

Заповеди сосуда, начертанные в `Dockerfile`:

- Дух обитает под именем `appuser`, а не под всевластием `root`
- В проде правит `gunicorn`, но лишь **одним** воркером: хроники живут в памяти процесса, и второй воркер расколол бы истину надвое
- `.dockerignore` не впускает в сосуд ни `.git`, ни `.idea`, ни — упаси Омниссия — `.env` с боевыми ключами
